## Исправление вкладок и публикация (2026-10-08)

Навигация `dashboard/index.html` теперь использует обычные `href="#..."` и CSS `:target` как резервный путь; JavaScript синхронизирует активную вкладку и хеш без зависимости от `CSS.escape`. Сценарий `scripts/check_browser.py` проверяет все 8 вкладок и переход на «Находки и гипотезы» при отключённом JavaScript. После повторного полного расчёта проходят 37 тестов, проверки валидации и браузерный сценарий без ошибок JavaScript. Полная SQLite хранится в переносимом ZIP, а сжатая копия `data/processed/corpus.sqlite.gz` подготовлена для GitHub. Добавлены корневой переход на отчёт и workflow публикации GitHub Pages. После загрузки проверить страницу Pages и релиз с ZIP; прямое включение Pages через API текущим токеном отклонено 403, поэтому используется workflow.

Публикация: содержимое репозитория загружено на GitHub. GitHub Pages не включился ни через API (403), ни через Actions (403). Загрузка ZIP как вложения релиза получила 401 от uploads.github.com. Поэтому ZIP хранится в репозитории частями `exports/quran-analysis-portable.zip.part-*` с SHA-256 и собирается `python scripts/assemble_archive.py`. Workflow Pages оставлен только для ручного запуска после включения GitHub Pages владельцем в Settings → Pages; README не ссылается на неработающий сайт.
