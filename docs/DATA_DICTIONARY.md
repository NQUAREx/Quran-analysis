# Словарь таблиц, единиц и навигации

Основная база: `data/processed/corpus.sqlite`. CSV.gz — переносимые полные таблицы; сжатие не является усечением. Точное определение профилей и символов — `COUNTING_RULES.md`. Поиск в интерфейсе и командой ниже возвращает исходные контексты, а не только итоговые числа.

| Таблица | Зерно, ключ и смысл |
|---|---|
| verses | Один исходный аят; verse_id=`surah_id:ayah_id`; raw_text сохраняет служебные знаки |
| tokens | Один орфографический токен; token_id=`verse_id:token_in_ayah`; поверхности raw/nfc/plain/search, координаты исходника |
| spans | Один исходный непробельный фрагмент либо пробельный участок; содержит токены и самостоятельные знаки; можно восстановить весь аят |
| source_records | Одна исходная запись с разделителями и переводом строки; связь с точными смещениями |
| surahs | Одна сура исходного файла; длины и пределы |
| profiles | Версионируемые правила преобразования |
| token_scopes | Один token_id × scope; отдельные порядковые индексы после изменения области включения |
| vocabulary | Одна форма × profile_id × scope; unit_id, частота, ранг, доля, число аятов/сур, пределы положения |
| occurrences | Одна форма unit_id × token_id; точный индекс в области; соединение с tokens/verses даёт весь контекст |

Внешняя морфология не изменяет эти таблицы. `morphology_segments.csv.gz` содержит принятые сегменты; отношения к исходным токенам и полный журнал выравнивания находятся в morphology-таблицах. Нельзя считать строки соединения с сегментами орфографическими токенами: один токен может иметь несколько сегментов, и выравнивание может быть групповым.

| Поле | Единица и правило |
|---|---|
| surah_id, ayah_id | Положительные исходные номера, не переводятся в даты |
| verse_id, token_id, segment_id, unit_id | Текстовые ключи; различные типы единиц имеют разные пространства ключей |
| global_ayah | Порядковый номер аята в файле с 1 |
| global_token, token_in_ayah, token_in_surah | Порядок токена в file с 1; сохраняется при фильтре, не выдаётся за порядок в numbered |
| scope_token_index, scope_token_in_ayah, scope_token_in_surah | Порядок в конкретном scope с 1 |
| raw_start, raw_end | Unicode-кодовые точки в полном исходном файле; 0-based [начало,конец), не байты |
| byte_start, byte_end | Отдельный UTF-8 байтовый индекс; 0-based [начало,конец) |
| letter_count | Письменные базовые буквы, не звуки; исходные raw-значения в БД |
| mark_count | Знаки Unicode M*; у аята все знаки, у токена только внутри его поверхности |
| frequency, count | Целое число вхождений указанной единицы и области; частоты разных единиц несопоставимы без знаменателя |
| share, relative_frequency | Доля с конкретным знаменателем из таблицы/методики; не процент, пока не умножено на 100 |
| ayah_count, surah_count | Число различных аятов/сур с хотя бы одним вхождением |
| is_opening_basmala | 1 только для четырёх токенов вступительного префикса, исключаемого в numbered |
| p_value | Monte Carlo хвост относительно указанной модели; (b+1)/(B+1) |
| p_adjusted | Holm-FWER по всем 24 строкам первичной семьи; это не FDR q-value |
| null_q025, null_q975 | Процентили распределения контрольной статистики; не доверительный интервал точного количества в файле |
| effect | observed − null_mean в единицах конкретной статистики |
| status, limitations | Статус и пределы вывода; exploratory не равняется независимому подтверждению |

Все прочие поля сопровождаются методикой семейства (`SEARCH_SPACE.md`, `STATISTICAL_PLAN.md`, `EXPLORATORY_PLAN.md`, `SOURCES.md`), заголовками таблиц, источником графика и вычисляющим модулем. Полная фактическая схема SQLite доступна через `.schema` или `PRAGMA table_info(tokens)`.

## Полные исходные вхождения

```bash
python -m quran_analysis.query --text 'الله' --profile plain --scope numbered --output allah.csv
python -m quran_analysis.query --unit character --text 'ّ' --profile raw --output shadda.csv
python -m quran_analysis.query --text 'الرحيم' --profile plain --surah 1
```

Символьный режим перечисляет каждую кодовую точку **внутри лексических токенов** (знаменатель совпадает с core_character_frequencies). Для raw известна точная исходная координата символа; для преобразованных профилей возвращается индекс внутри производного токена и исходный диапазон всего токена, без ложного побуквенного соответствия после NFC. Самостоятельные служебные знаки доступны через `spans` и Unicode-инвентарь. SQL-примеры — `QUERIES.sql`.
