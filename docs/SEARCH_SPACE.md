# Конечное пространство описательных поисков C–H

Модуль `src/quran_analysis/exploration.py` читает готовую `data/processed/corpus.sqlite` в режиме `mode=ro`. Он не заменяет исходный текст и не изменяет общую базу. Параметры берутся из `config/analysis.json`; все разрешённые значения, включая значения по умолчанию, записаны в `results/exploration_summary.json` → `config`. Неизвестные настройки, конфликтующие псевдонимы, недопустимые диапазоны и неподдерживаемая глубина формул вызывают ошибку.

`complete_within_scope` означает полный перебор **указанного конечного множества**, а не выполнение всех возможных исследований соответствующего направления. `partial_bounded_search` означает ограниченный поиск кандидатов. Этот документ относится только к exploration; морфология, статистические проверки и дополнительные направления имеют собственные реестры покрытия.

По умолчанию здесь используются профиль `plain` и область `file`, то есть вступительные басмалы остаются в тексте. `plain` — письменная поверхность без заданных огласовок/редакторских знаков, не лемма и не корень. Только полные повторы аятов сравниваются во всех четырёх профилях и обеих областях. Параметры и числа ниже относятся к выполнению конфигурации проекта.

## C. Повторы

| Поиск | Конечное множество и правила | Выполнено |
|---|---|---:|
| Словесные n-граммы | n = 2, 3, 4, 5; все начала внутри каждого аята; границы аятов не пересекаются | 251 513 вхождений; 200 945 разных последовательностей |
| Буквенные n-граммы | n = 2, 3, 4; только внутри токена; символы Unicode категории Letter, кроме U+0640; комбинируемые знаки пропускаются | 540 963 вхождения; 23 933 последовательности |
| Полные повторы аятов | 6 236 аятов × `raw/nfc/plain/search` × `file/numbered` | 49 888 сравниваемых представлений; 772 строки групп повторов |
| Длинные точные повторы | Все пары одинаковых пятисловных затравок с поддержкой 2–40; расширение в обе стороны до несовпадения или границы аята; минимум 8 слов | 7 282 пары затравок; 388 разных расширенных пар; 264 разные фразы |
| Приблизительные пары | Аяты длиной ≥5 токенов; общая трёхсловная затравка, встречающаяся в 2–25 подходящих аятах | 18 086 пар кандидатов |

`frequency` считает все перекрывающиеся вхождения. `nonoverlapping_frequency` считает максимальное неперекрывающееся подмножество **отдельно для каждой фразы**: жадно выбирается самое раннее начало, затем первое начало не раньше конца выбранного вхождения. Равная длина интервалов делает этот алгоритм точным. Для слов и длинных фраз правило применяется отдельно в каждом аяте, для букв — отдельно внутри каждого токена. Полный журнал вхождений сохраняет также отброшенные этим вариантом перекрытия.

`word_ngram_occurrences` содержит адреса первого и последнего токенов каждой n-граммы. `letter_ngram_occurrences` содержит адрес токена, номер первой буквы с 1 и полуоткрытые смещения в строке **plain**, с 0. Эти смещения не являются смещениями исходного файла: для него используются `token_id` и таблицы core.

В `raw/file` сравнивается полный `raw_text`, включая пробелы и отдельные редакторские знаки. В остальных семи вариантах сравнивается последовательность профильных токенов, соединённых одним пробелом. Поэтому различия результатов отражают и профиль, и явно описанное правило представления. В `numbered` удаляются только токены с `is_opening_basmala=1`.

Поиск длинных повторов ограничен частотой затравок: фраза без допустимой затравки может не попасть в кандидаты. Это не глобальный суффиксный поиск всех максимальных повторов. Для **каждой найденной фразы** затем заново извлекаются все её точные вхождения, включая те, которые не участвовали в расширении. `long_repeats` хранит все эти адреса; `long_repeat_pairs` — только обнаруженные расширением пары и расстояние начал в глобальных токенах. Один и тот же длинный повтор может включать другую найденную фразу.

Для всех приблизительных кандидатов вычисляется Jaccard множеств слов. Только при Jaccard ≥0,4 выполняется `difflib.SequenceMatcher(autojunk=False)` над последовательностями токенов: 804 выравнивания, 17 282 пары отсеяны до выравнивания. Мера равна `2*M/(len(a)+len(b))`, где M — число совпавших элементов выбранных SequenceMatcher блоков. Она не равна редакционному расстоянию, может зависеть от порядка аргументов; более ранний аят всегда первый. Таблица кандидатов содержит все пары, пустая оценка означает пропуск выравнивания. Таблица высокой близости содержит все 134 пары с `0,8 ≤ ratio < 1`; точные совпадения остаются в общем журнале. Изменённые блоки и их координаты сохранены в `differences_json`.

Сквозные и межсловные буквенные n-граммы, n-граммы других профилей, перебор всех приблизительных пар и последовательности лемм/корней этим модулем не выполняются.

## D. Положение и концентрация

Полностью обработаны все 14 868 форм `plain`: 78 248 строк отдельных вхождений и интервалов, первые/последние адреса, максимальная длина отсутствия с учётом начала и конца корпуса, интервалы в токенах, аятах и сурах. В `word_occurrence_gaps` интервалы считаются между последовательными токенами, поэтому интервалы аятов/сур могут быть нулевыми. В сводной таблице `positions` максимальные интервалы аятов/сур считаются между различными занятыми единицами. Токенный интервал — разность позиций; длина отсутствия между вхождениями на единицу меньше.

Нормализованная позиция равна `(i−1)/(N−1)`; для единицы длиной 1 используется 0. Треть определяется `min(2, floor(3*(i−1)/N))`. Считаются трети аята, суры и корпуса, как абсолютные частоты, так и частоты на 10 000 доступных токенов соответствующих третей. Знаменатели всех трёх разбиений сохранены в summary. Разбиения относятся к токенным позициям, а не равному числу аятов. Диапазоны частоты формы: 1, 2–9, 10–99, ≥100.

Окна концентрации имеют 1 000 глобальных токенов и шаг 250. Дополнительно включается последнее полное окно, заканчивающееся на последнем токене: всего 310 окон. Они могут пересекать границы сур; это явно сквозной **позиционный**, а не n-граммный анализ. Для короткого входа используется одно окно со своим реальным знаменателем. Для каждого слова сохраняются все начала окон с максимальной частотой.

Концентрация по сурам: `HHI = Σ_s p_s²`, где `p_s` — доля вхождений формы в суре; `KL = Σ_s p_s log2(p_s/q_s)`, где `q_s` — доля всех токенов корпуса в суре. KL учитывает различный доступный объём текста, но не даёт статистической значимости. Поиск точек изменения, попарное сходство распределений всех слов, позиционные характеристики корней и последовательностей в этот модуль не входят.

## E. Границы и формальная композиция

Для каждого аята сохранены начало и конец из 1, 2 и 3 слов и из 1, 2 и 3 письменных букв, если длина позволяет: 23 712 групп. Буквенные границы строятся после удаления пробелов и комбинируемых знаков. Это письменные окончания, без фонетической интерпретации.

Для всех 6 236 аятов сохранены длина в токенах и буквах, число форм, энтропия, первое/последнее слово, равенство этих слов и точный палиндром токенной последовательности. Буквенные длины взяты из базового подсчёта core (Unicode Letter исходной записи, без татвиля).

Для каждой из 114 сур сравниваются зеркальные позиции `a` и `A+1−a`: 3 091 пара. Проверяются равенства токенных/буквенных длин и полных последовательностей. Центр при нечётном числе аятов исключается и из зеркальных пар, и из обеих половин; его адрес сохранён. Первой и второй половинами считаются первые и последние `floor(A/2)` аятов. Сохраняются их токенные объёмы и Jaccard множеств форм; неодинаковая длина половин не скрывается.

Оптимизация центра/границы, смысловые кольцевые композиции, хиазмы и подтверждённая модель рифмы здесь не исследуются. Признаки длины и лексики сохранены для дальнейшего воспроизводимого сравнения; само наличие этих признаков не означает выполненный тест каждой возможной связи.

## F. Точная целочисленная грамматика

Единица перебора — одна сура. Атомы: `surah_id`, `verses`, `tokens`, `letters`, `types`, `first_global_ayah`, `last_global_ayah`, `cumulative_tokens`. Последний атом — накопленное число токенов до конца данной суры в порядке файла. Все значения целые; округления, допуски и исключения отдельных сур отсутствуют. Полная грамматика также записана в `exploration_coverage.json` → направление F.

Разрешены только атом `x` и сумма `x+y`, максимальная глубина операции 1. В суммах допускается `x=y`; порядок слагаемых не различается. Каждое выражение сравнивается на точное равенство с каждым атомом `z`. Саморавенства `x=x` и обратные копии атомарного сравнения исключены. Констант в равенствах нет. Следовательно, для восьми атомов на суру есть `C(8,2) + C(9,2)*8 = 316` сравнений; всего 36 024, из которых 14 совпадают. Структурные зависимости атомов не исключаются постфактум, поэтому совпадения остаются описательными.

Для каждого атома проверяются делимость и остаток по 2, 3, 5, 7, 11, 19, а также простота: 5 472 проверки делимости (1 208 совпадений) и 912 проверок простоты (165 совпадений). Общий журнал содержит все 42 408 положительных и отрицательных результатов. Никакое число найденных совпадений не используется как p-value.

Равные частоты слов сохраняются 171 классом эквивалентности с полным списком форм и числом пар `k*(k−1)/2`; пары однозначно раскрываются через `itertools.combinations(members,2)`. Деление, отношения произвольных выражений, умножение, перестановки цифр, абджад, произвольные константы и лингвистическая интерпретация числительных этим поиском не выполняются.

## G. Совместная встречаемость и сходство сур

Словарь: первые 120 форм по убыванию токенной частоты `plain/file`; при равенстве — лексикографический порядок. Стоп-слова не удаляются. Во всех контекстах используется **бинарное присутствие** слова, независимо от числа повторений внутри контекста.

Контексты: все 6 236 аятов; все 114 сур; все 1 505 полных неперекрывающихся 50-токенных окон, отсчитываемых отдельно от начала каждой суры. Хвосты короче 50 токенов не включаются, окна между сурами не склеиваются. Для каждого вида контекста сохранены все `C(120,2)=7 140` пар, включая нулевые связи: всего 21 420 строк.

`lift = count_ab*N/(count_a*count_b)`; `PMI = log2(lift)` для ненулевой совместной частоты. При нулевом пересечении PMI пуст, lift равен 0 при ненулевых маргинальных частотах. Порог поддержки 5 отмечается полем `support_pass`; слабые пары не удаляются из журнала, но не попадают в выборку лучших ассоциаций. Сохранены обе маргинальные частоты, совместная частота, число контекстов и до пяти конкретных примеров.

Эти меры учитывают индивидуальные частоты, однако различная длина аятов/сур остаётся источником смешения. 50-токенные окна дают сравнение при фиксированном объёме, но не заменяют формальную модель условной независимости. Значимость, причинная или смысловая связь не заявляется; леммы и корни сюда не входят.

Все 6 441 неупорядоченные пары сур сравниваются косинусом TF–IDF. TF — абсолютная частота формы; `IDF=ln((1+114)/(1+df))+1`; векторы нормируются по L2. В таблице сохранены общие формы (их число), длины обеих сур, признак соседства и мера. Кластеризация, графовые сообщества и проверка устойчивости кластеров не выполняются.

## H. Информационные свойства

Энтропия нулевого порядка вычисляется как `−Σ p log2 p`; perplexity равна `2**H`. Сохранены корпус и 114 сур. TTR (`types/tokens`) описательный и не используется для ранжирования сур разной длины. Рост словаря измеряется через каждые 100 токенов, плюс конечная позиция: 783 строки. Это порядок файла, без усреднения по перестановкам.

Для сравнимого объёма выделены 110 полных неперекрывающихся 500-токенных окон внутри сур; короткие суры и хвосты исключены. Для каждого окна сохранены адреса границ, число форм, TTR и энтропия. Эти окна отличаются от 50-токенных окон совместной встречаемости и 1 000-токенных окон концентрации.

Сжатие: `plain` токены всего файла соединены одним ASCII-пробелом, закодированы UTF-8, сжаты `zlib` с уровнем 9. Сравниваются наблюдённый порядок и 19 глобальных перестановок токенов, `random.Random(seed=20261007)`. Частоты и байтовая длина сохраняются, границы и грамматика разрушаются. Сохранены все 20 результатов. Это описательное сравнение с определённым контролем; его нельзя трактовать как доказательство уникальности корпуса. Точный размер сжатия может зависеть от версии zlib.

Степенной закон, конкурирующие параметрические модели распределения, автокорреляции и спектральные пики этим модулем не проверяются. Ранговые частоты находятся в основном каталоге core; по виду логарифмического графика закон не устанавливается.

## Контракт результата и проверка

`results/exploration_summary.json` — объект со следующими ключами:

- `profile_id`, `scope`, `config`, `seed` — исходная область и разрешённые параметры.
- `tables` — объект `{table_name: {path: string, rows: integer}}`, относительные пути от корня проекта; 25 таблиц.
- `word_ngram_occurrences`, `letter_ngram_occurrences`, `long_repeat_groups`, `long_repeat_seed_pairs`, `approximate_candidate_pairs` — целые счётчики.
- `repeat_inventory` — объект с ключами `profile/scope` и полями `repeated_groups`, `verses_in_groups`.
- `approximate_counts` — `aligned`, `skipped_below_jaccard`, `high_similarity_nonidentical` (для пустого события ключ может отсутствовать).
- `top_word_ngrams`, `top_repeated_verses`, `top_long_repeats`, `top_approximate`, `top_surah_similarity`, `top_cooccurrence` — массивы примеров; полные журналы доступны через `tables`.
- `numeric_counts` — по три пары счётчиков `equality/divisibility/primality` с суффиксами `_tested` и `_matched`; `numeric_examples` — первые не более 30 совпавших равенств в порядке обхода.
- `information` — строка корпусных информационных свойств; `compression` — все строки сравнения сжатия.
- `within_ayah_thirds_denominators`, `within_surah_thirds_denominators`, `corpus_thirds_denominators` — тройки целых знаменателей.
- `duration_seconds` — время выполнения, не часть содержательной воспроизводимости.

`exploration_coverage.json` содержит явные границы каждого поиска. `hypotheses/exploration.json` содержит пять описательных карточек; `p_value=null` во всех пяти. `tests/test_exploration.py` проверяет разрешение параметров, точный размер пространства формул, нулевые и бинарные совместные частоты, полные окна у границы, перекрывающиеся повторы, а также целый запуск на маленьком корпусе с проверкой координат, счётчиков всех выходных таблиц и неизменности исходной SQLite. Для рабочего корпуса отдельная сверка сохранена в `results/exploration_checks.json`.

Повторный запуск из любого каталога:

```bash
PYTHONPATH=/workspace/Quran-analysis/src python -m quran_analysis.exploration --root /workspace/Quran-analysis
```
